## El prompt que las produjo

```
Solo explorar, sin editar nada. En fzf quiero agregar una acción clear-history
que se bindee con --bind. Trazá cómo viaja una acción que ya existe, prev-history,
desde el parseo hasta que se ejecuta. Devolveme notas con tres secciones: módulos
tocados, interfaces usadas y riesgos. Cada afirmación con archivo:línea.
```

Cuatro cosas lo hacen funcionar: el modo **solo lectura** explícito, un cambio **concreto**,
una acción existente para **trazar como guía** (en vez de "explorá el repo"), y la
exigencia de **archivo:línea**, que es lo que después permite verificar las notas.

## Qué se quiere lograr

`fzf` guarda el historial de búsquedas con `--history=ARCHIVO`, y se navega con
`prev-history` / `next-history`. **No hay forma de borrarlo desde adentro**: hay que salir
y hacer `rm` del archivo a mano.

Queremos una acción `clear-history` que se pueda bindear como cualquier otra:

```bash
fzf --history=/tmp/h --bind 'ctrl-alt-d:clear-history'
```

## El terreno

`fzf` son ~33.000 líneas de Go en 88 archivos bajo `src/`. No hace falta entenderlo
entero: hace falta entender **el camino que recorre una acción**, de la línea de comandos
hasta que se ejecuta.

```
--bind 'tecla:accion'
        │
        ▼
  src/options.go        parsea el nombre y lo mapea a una constante
        │
        ▼
  src/terminal.go       declara la constante y la ejecuta en el switch
        │
        ▼
  src/history.go        el módulo que haría el trabajo real
```

## Hallazgos

### 1 · Dónde se parsean las acciones

**`src/options.go:1909-1912`** — un `switch` gigante sobre el nombre textual de la acción:

```go
case "prev-history", "previous-history":
	appendAction(actPrevHistory)
case "next-history":
	appendAction(actNextHistory)
```

Agregar una acción nueva es agregar un `case` acá. Es el patrón que sigue el archivo
entero, sin excepciones.

### 2 · Dónde se declaran las constantes

**`src/terminal.go:557`** declara `type actionType int`, y las constantes viven en el
bloque que arranca ahí — `actPrevHistory` en la línea **716**, `actNextHistory` en la
**720**.

### 3 · ⚠ El enum tiene código generado

**`src/terminal.go:556`**, justo arriba del tipo:

```go
//go:generate stringer -type=actionType
```

Y **`src/actiontype_string.go`** abre con:

```
// Code generated by "stringer -type=actionType"; DO NOT EDIT.
```

Ese archivo contiene índices posicionales (`_ = x[actPrevHistory-149]`). **Agregar una
constante en el medio del bloque desplaza todos los índices siguientes.** No se edita a
mano: se regenera con `make generate` (corre `go generate`, y necesita `stringer` instalado:
`go install golang.org/x/tools/cmd/stringer@latest`).

**Este es el hallazgo que un agente sin explorar se pierde**, y el que rompe el build de
forma confusa si se ignora.

### 4 · Dónde se ejecutan las acciones

**`src/terminal.go:7851-7862`** — el switch de ejecución:

```go
case actPrevHistory:
	if t.history != nil {
		t.history.override(string(t.input))
		t.input = trimQuery(t.history.previous())
		t.cx = len(t.input)
	}
```

El guard `t.history != nil` es el patrón obligado: **el historial puede no existir**, si
el usuario no pasó `--history`. Cualquier acción nueva lo tiene que respetar.

### 5 · El módulo de historial

**`src/history.go`**, 95 líneas enteras. La estructura y sus métodos:

| Miembro | Qué hace |
|---|---|
| `NewHistory(path, maxSize)` | Lee el archivo; si no existe lo crea con permisos `0600` |
| `append(line)` | Agrega y **persiste** con `os.WriteFile(h.path, …, 0600)` |
| `override(str)` | Modifica en memoria, **no escribe** |
| `current()` / `previous()` / `next()` | Mueven el cursor |

`append` es el único que toca el disco, y es el modelo a copiar: mismo path, mismos
permisos `0600`.

**Ojo con cuándo se llama:** `src/terminal.go:6572-6574` lo invoca **al salir**, si el
código de salida es 0 o 1 (se aceptó una selección, o no hubo match). O sea que la query
actual se escribe en el historial al terminar la sesión. Salir con `ESC` (código 130) no
escribe nada.

### 6 · Dónde se construye el historial

**`src/options.go:2537-2543`** — el closure `setHistory`, invocado desde el `case
"--history"` en la línea **3108**. `--no-history` (línea **3106**) lo pone en `nil`.

### 7 · Los defaults de teclas

**`src/options.go:3794-3800`** — cuando hay `--history`, `CTRL-P` y `CTRL-N` se bindean
solas a `prev-history` / `next-history`.

**Decisión de alcance:** `clear-history` **no** debería tomar una tecla por default. Un
borrado accidental de historial no se deshace.

### 8 · La documentación

**`man/man1/fzf.1:2030`** — sección `.SS AVAILABLE ACTIONS:`, con una entrada por acción
(la de `prev-history` está en la **2111**):

```
    \fBprev\-history\fR                 (\fIctrl\-p\fR on \fB\-\-history\fR)
```

Ojo con el roff: los guiones van escapados como `\-`. Buscar `prev-history` literal no
encuentra nada; hay que buscar `prev\-history`.

### 9 · La capa de portabilidad

`src/` separa por plataforma en cinco archivos: `proxy_unix.go`, `proxy_windows.go`,
`terminal_unix.go`, `terminal_windows.go`, `winpty_windows.go`.

**`src/history.go` no es uno de ellos**: usa `os.ReadFile` / `os.WriteFile`, que andan en
todas las plataformas. El cambio es multiplataforma sin esfuerzo — pero conviene decirlo
explícito en la spec, porque no revisarlo sería suerte, no diseño.

### 10 · La línea de base de regresión

**`Makefile:90`** — el target `test`:

```bash
make test
```

Corre los tests de Go de `src`, `src/algo`, `src/tui` y `src/util`. Hay además tests de
integración en Ruby bajo `test/`, y `test/test_core.rb:525` tiene `test_history`, que
ejercita `--history` y `--history-size` de punta a punta.

Esos tests de integración corren con `make itest` (`Makefile:97`) y manejan `fzf` desde
una sesión de `tmux`, así que necesitan Ruby y `tmux` instalados. Uno solo se corre con
`ruby test/test_core.rb -n test_history`.

**`Makefile:113`** — `make lint`, que exige `gofmt -s` sobre `src/`, y además corre
`rubocop` sobre los tests Ruby y chequea los scripts de shell. Necesita `bundle install`.

## Riesgos

| Riesgo | Por qué |
|---|---|
| **Romper el enum generado** | Si se edita `actiontype_string.go` a mano o no se regenera, el build falla con errores de índice que no señalan la causa |
| **Historial nulo** | Sin el guard `t.history != nil`, la acción panica cuando no hay `--history` |
| **Borrado accidental** | Es una operación destructiva e irreversible sobre un archivo del usuario |
| **Reescritura al salir** | `append` corre al terminar la sesión: si se vacía el historial y después se acepta con una query, el archivo ya no queda vacío |
| **Desalinear el estado en memoria** | Truncar el archivo sin resetear `lines`, `modified` y `cursor` deja la sesión mostrando entradas que ya no existen |

## Lo que NO hace falta entender

El motor de matching (`src/algo/`), la capa de TUI (`src/tui/`), el preview, el server
HTTP (`src/server.go`) y las ~8.800 líneas de `src/terminal.go` que no son el switch de
acciones.

Acotar también es decidir qué no leer.
